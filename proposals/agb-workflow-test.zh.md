# AGB 流程测试：设计

日期：2026-11-05。状态：待拍板。上一轮结果见 [results/agb-findings.md](../results/agb-findings.md)。

## 1. 为什么要再测一次

上一轮测的是「AGB 装在项目里，AI 接到一个故事」。结果 AI 一样 AGB 的东西都没用：没敲 `agb`、没查知识库、没走斜杠命令、没提交，所以门禁也没触发。成绩跟原版手册 A 差不多，这说明的是「这样用 AGB 等于没用」，不说明 AGB 本身好不好。

AGB 是一条流水线：规格 → 架构 → 任务拆解 → 测试设计 → 编码（`agb run`）→ 交付。它的价值在流水线里：每个任务单独提交、提交前过门禁、每个任务有只读会话从外面验收、每个域收尾做安全审查、停下的条件写在代码里。要公平评价它，就得让它走完自己的流程。

这一轮要回答三个问题：

| # | 问题 | 怎么回答 |
|---|---|---|
| Q1 | 按 AGB 自己的流程走，同样的题能不能做对？花多少钱、多少时间？ | A 轨：同样四道题，同样的隐藏评分 |
| Q2 | 跟 v2.1 的故事流程比，好在哪、差在哪？ | A 轨对照 v2.1-spec 已有的 8 场 |
| Q3 | 放进 anifit-platform 这种真项目，代价是什么？ | 记录 AGB 往仓库里加的东西；B 轨（可选）在真平台的副本上跑 |

## 2. 公平原则

**按 AGB 手册的方式跑，只在三处跟其他方案统一。**

统一的三处：

1. **考题**：T1、T2、T3、T6 的内容不变，改写成一份「变更需求」文档放进考场。
2. **评分**：同一套隐藏测试、同样的成功定义（`pnpm check` 全过 + 隐藏硬测试全过 + 要求的验收标准有测试）。
3. **代答人规则**：需要人拍板时，用同一条固定规则代答（见第 5 节），并记下次数。

按 AGB 手册来的地方：

| 项 | 怎么做 | 和上一轮的区别 |
|---|---|---|
| 入场模式 | 二次开发（`mode: brownfield`），规格阶段的输入是变更需求 | 同上一轮 |
| 斜杠命令 | 规格、架构、测试设计带 `--accept-recommended` | 上一轮没走 |
| 编码 | 在终端里直接跑 `agb run`，前台、不 detach | 上一轮禁止 |
| 权限 | 用 `agb init` 写的「整个 shell 放行」 | 上一轮用统一白名单 |
| 模型 | AGB 默认：规格和升级用 opus，编码用 sonnet | 上一轮全 opus |
| 验收会话、安全审查 | 开着（默认） | 上一轮不涉及 |
| 交付阶段 | 跑，但**不计入成功**，只记它会不会被拦、为什么 | 上一轮不涉及 |

**偏离手册的地方，以及理由：**

- **不走 `/agb-skills:agb-code`，直接跑 `agb run`。** 那个斜杠命令会在后台起跑、出错时自己去修 AGB 本身、给 AGB 仓库开 PR。考试里不能让它改考官手里的工具。手册也写了可以在终端里自己跑。
- **AGB 版本钉在 `90d5772`。** 它每天都在更新，跑到一半换版本会让结果不可比。
- **额度用完不等待**（`AB_USAGE_WAIT_MAX_H=0`）。默认它会等最多 168 小时。

## 4. 一场 AGB 流程考试怎么跑

### 4.1 搭考场

和上一轮一样：fixture + 共享文档 + layout-agb，`agb` 装好，`mode: brownfield`。多出两件事：

1. **变更需求文档** `docs/requests/AN-90x.md`：从 `task.json` 的题目原文改写，保留每一句具体要求（函数名、字段名、返回值）。AGB 的 `prd-content-preserved` 门禁保证它不改写原话，隐藏测试依赖这些名字。
2. **保留 `.claude/settings.local.json`**（整个 shell 放行），并且 harness 加载 local 设置。

### 4.2 阶段会话（规格、架构、任务、测试设计）

每个阶段一次 `claude -p`，提示词就是斜杠命令本身，例如：

```text
/agb-skills:agb-spec --accept-recommended 变更需求在 docs/requests/AN-900.md
```

每次阶段结束后 harness 检查三件事：

| 检查 | 怎么查 | 不满足怎么办 |
|---|---|---|
| 阶段产物在不在 | `agb status` | 记为「阶段未完成」，这场失败，停 |
| 有没有挡路的问题 | `.ab/questions.json` 里没答的、挡这个阶段的 | 进代答循环（第 5 节） |
| 有没有提交 | `git log` | 只记录，不干预 |

任务拆解阶段（`/agb-skills:agb-tasks`）的命令不带 `--accept-recommended`，它问的问题同样走代答循环。

### 4.3 编码

```bash
agb run
```

前台跑，harness 等它结束，读 `.ab/run/stop.json` 判断停因：

| 停因 | 怎么处理 |
|---|---|
| 全部完成 | 进评分 |
| 要人回答的问题 | 代答循环，然后 `agb run --resume`。最多 3 轮 |
| 环境问题（缺依赖、权限） | 不替它修，记下原因，这场失败 |
| 某任务反复失败 | AGB 自己会重试、换会话；它停下了就记为失败 |
| 额度用完 | 这场作废，额度恢复后重跑 |

### 4.4 交付（不计分）

跑 `/agb-skills:agb-delivery`（它和任务拆解一样不带 `--accept-recommended`，问题走代答循环），只记两件事：它会不会被拦（未复核的机器裁决、未关的安全发现），以及生成了哪些交付物。手册规定机器裁决要人复核才能交付，所以预期它会被拦，这本身就是一个要报告的事实。

### 4.5 评分

1. 复制隐藏测试，跑 `pnpm check` 和隐藏测试，规则和其他方案完全一样。
2. 额外跑 AGB 自己 CI 档的门禁：`agb check --all` 和 `agb build`，记 hard 和 partial 数。
3. 读 AGB 自己的运行报告（`agb report --run`）里的质量评分，作为参考，不进成功判定。

## 5. 代答人规则

AI 在 `-p` 模式下没法弹窗问人，问题会写进 `.ab/questions.json` 然后停。harness 这时扮演代答人：

1. 先跑 `/agb-skills:agb-questions --accept-recommended`：带推荐的问题全部按推荐定。
2. 剩下没有推荐的（开放取值、要密钥的）：用和 v2.1 实验一样的固定规则答：「取与 `docs/conventions/` 和模块文件一致的选项；它们没说的，取问题里提议的那个」。密钥类问题：考场里不需要任何外部密钥，答「不需要，用 fake」。
3. 每答一条记一次「人工介入」。同一场最多 3 轮代答，超过就停，记为失败。

这条规则让 AGB 和 v2.1 都在同样的「代答人」下工作，代答次数本身就是一个比较项：问得越多，真用起来人越累。

## 6. 隔离和权限

### 6.1 必须隔离个人设置

AGB 的编码会话启动 `claude` 时**不限定设置来源，也不限定 MCP**（`executors/claude-code.ts` 的 `claudeArgs`）。不隔离的话，你本机的全局 `CLAUDE.md`、context-mode 插件和它的钩子都会进 AGB 的每个会话，结果就不是 AGB 的结果了。

做法：每场考试用一个空的配置目录：

```bash
CLAUDE_CONFIG_DIR=<考场>/.lab-claude-config
```

空目录里没有登录信息，所以需要一个令牌。**这一步要你自己做**（我不能替你生成凭据）：

```bash
claude setup-token
```

把输出的令牌放进环境变量 `CLAUDE_CODE_OAUTH_TOKEN` 再启动实验。harness 已经会把这个变量传给子进程。

### 6.2 整个 shell 放行的风险

AGB 默认给整个 shell 放行，这是它的设计：编码要跑几小时，不能每条命令都等人批。代价是 AI 在你机器上能跑任何命令。考场在临时目录，没有 git 远程，没有密钥，但 AI 仍然可以访问考场以外的文件和网络。

两个选项：

| 选项 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A 本机 | 跟 AGB 用户的实际用法一样 | 零额外工作；结果最贴近真实使用 | AI 在你机器上有完整 shell |
| B 容器 | 考场、agb、claude 都放进 Docker | 隔离彻底 | 要先做一个镜像（Node、pnpm、claude、agb、离线 pnpm 仓库），约半天；容器里跑得慢一些 |

**推荐 A，只用于试点。** 试点只有 1 场、可以盯着看。A 轨的 8 场再看试点里 AI 实际跑了哪些命令，决定要不要换 B。

### 6.3 花费看门狗

AGB 的 $50 硬上限已经撤掉（`types.ts`，2026-10-17），它自己不会停。harness 加一个看门狗：每分钟读一次 AGB 自报的累计花费（`.ab/run/state.json` 里的 `costUsd`）加上阶段会话的花费，超过单场上限就结束整组进程，这场记为「超预算」。

## 9. 已知的效度风险

1. **考场不对 AGB 的胃口。** `agb stack` 在考场上认不出后端框架、API 形态和构建脚本：考场是一个只有模块函数、没有 HTTP 接口的领域库。结果是 AGB 的接口契约、端点覆盖、构建这几道门禁「探测不到就不报」，它的一部分长处用不上。试点要记下哪些门禁实际跑了。B 轨在真平台上跑，就是为了补这一条。
2. **小任务撞上域划分阈值。** `.abrc.json` 的 `subsystem` 默认要 15 个接口、2 个域才算子系统。四道题都很小，AGB 可能把整道题当一个域、一个会话，分域的好处体现不出来。
3. **样本小。** 每格 2 场，看趋势可以，下结论不行。
4. **AGB 自己的会话不在 harness 的记录里。** `agb run` 起的会话不经过 harness，对话记录在 AGB 自己的 `.ab/run/` 下。评分前把整个 `.ab/` 复制进结果目录。
5. **花费估计不准。** 下面的数字是猜的，试点之后用真数字替换。
